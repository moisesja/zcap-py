## Review

**Outcome**: Issue #6 is implemented. The W3C-flat JCS payload assembly now lives in exactly one public function (`build_canonical_payload`); a public signing API (`sign_document_proof`) wraps it; the verifier and test helpers all call through it. Wire bytes are bit-identical to before.

**Files changed**:
- `src/zcap_py/proof/ed25519_2020.py` — added `build_canonical_payload` + `sign_document_proof`; collapsed the inlined assembly in `verify_document_proof`.
- `src/zcap_py/__init__.py` — re-exported both functions.
- `tests/conftest.py` — `make_proof_value`/`make_signed_document`/`make_misbound_document` now delegate to `sign_document_proof`. Signatures preserved → no other test module touched.
- `examples/generate_cross_lang_fixture.py` — replaced inlined `_sign_document` body with calls to the public API.
- `tests/test_cross_language_interop.py` — `test_signature_canonicalizes_to_known_jcs_bytes` now exercises the public `build_canonical_payload`.
- `tests/test_public_proof_api.py` — new module, 3 cases.
- `CHANGELOG.md` — documented under `[Unreleased]`.

**Validation evidence**:
- `uv run pytest` → 265 passed (3 new + 262 existing). Zero regressions.
- `uv run ruff check` → all checks passed on every changed file.
- `uv run mypy` (strict) → no issues found in 26 source files.
- Byte-stability: SHA-256 of both `tests/fixtures/cross_lang_jcs/*.json` after refactor matches the captured pre-refactor baseline (`b7bb21c0...`, `41b1128a...`). Proof that the public API path produces bit-identical bytes to the previous inlined code.

**Design notes**:
- `build_canonical_payload(document, proof)` accepts either the wire document (with `proof`) or the body alone. It always strips `document["proof"]` and uses the supplied `proof` argument, after dropping `proofValue` from it. Symmetric verifier and signer both pass this without dance.
- `sign_document_proof` deliberately disallows pre-supplied `proofValue` in `proof_metadata` by computing and overlaying it; documented in the docstring.
- The conftest shims preserve their old signatures so the existing 70+ test cases that depend on them keep passing without edits — minimal-impact refactor per AGENTS.md.

**Out of scope** (per the issue): URDNA2015 path (`verify_document_proof_w3c`) and non-Ed25519Signature2020 proof types — different signing-input shapes, separate follow-ups if needed.
