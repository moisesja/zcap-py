## Review

**Outcome**: All tasks completed and validated. Issue #5 is implemented as a pure test/fixture-infrastructure change with zero runtime impact on `zcap_py`.

**Files added**:
- `examples/generate_cross_lang_fixture.py` (167 lines)
- `tests/fixtures/cross_lang_jcs/capability_v1.json` (signed delegated capability with caveat[], parentCapability, expires, capabilityChain, plus extra `nonce` field on proof)
- `tests/fixtures/cross_lang_jcs/invocation_v1.json` (signed invocation with proof carrying capability, capabilityAction, invocationTarget, capabilityChain, plus extra `nonce`)
- `tests/test_cross_language_interop.py` (4 parametrized cases, ~50 lines)

**Validation evidence**:
- `uv run pytest tests/test_cross_language_interop.py -v` → 4 passed (jcs-bytes-match × 2 + signature-verify × 2).
- `uv run pytest` → 262 passed (4 new + 258 existing). No regression.
- Idempotent regen: SHA-256 of both fixtures matches before/after re-running the generator (`b7bb21c0...` and `41b1128a...`).
- `uv run ruff check` and `uv run mypy --strict` both clean on the new files.

**Design notes**:
- Followed the parser's reality on invocation shape (`capabilityAction` in proof only, not body) rather than the issue's brief gloss, because the fixture must round-trip through the existing `verify_document_proof`.
- Fixture's `document` value is a JSON-encoded string (not a nested object) so it matches the issue's prescribed test code (`json.loads(fixture["document"])`) and lets the dotnet companion test compare against exact bytes.
- The extra `nonce` field on proof is deliberately included — locks down the "every non-`proofValue` field is JCS'd" invariant against silent drops.

**Coordination note** (no code change): the dotnet companion (zcap-dotnet#34) needs the fixture to verify it once landed; this PR ships the fixture standalone so it can land independently.
